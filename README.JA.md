# Workout Planner

[English](README.md) · [العربية](README.AR.md) · [Čeština](README.CZ.md) · [Dansk](README.DA.md) · [Deutsch](README.DE.md) · [Español](README.ES.md) · [Français](README.FR.md) · [हिन्दी](README.HI.md) · [Bahasa Indonesia](README.ID.md) · [Italiano](README.IT.md) · 日本語 · [한국어](README.KO.md) · [Nederlands](README.NL.md) · [Norsk bokmål](README.NO.md) · [Polski](README.PL.md) · [Português (Brasil)](README.PT-BR.md) · [Português (Portugal)](README.PT.md) · [Română](README.RO.md) · [Русский](README.RU.md) · [Shqip](README.SQ.md) · [Türkçe](README.TR.md) · [Українська](README.UK.md) · [简体中文](README.ZH.md) · [繁體中文](README.ZH-TW.md)

**Obsidian のためのオールインワンのワークアウト記録ツール。** ウェイトトレーニング、ランニング、サイクリング、ヨガ、独自のフィールドを持つエクササイズまで。スマートフォンからセットを記録し、ガイド付きセッションに沿ってトレーニングし、グラフ、ダッシュボード、筋肉ヒートマップで進捗を確認できます。CSV は 1 つ、対応言語は 24 です。

スマートフォン向けに作られています。トレーニング中に各セット、ラン、ポーズを記録し、トレーニングを計画しているのと同じノートの中で、表、グラフ、ダッシュボードから進捗を確認できます。セットは、保管庫内の 1 つの CSV ファイルに保存されます。アカウントもクラウドも不要です。

グラフでは傾向がわかり、筋肉ヒートマップでは鍛えた部位がわかります。各セットは、それぞれの kg/lb の単位を保持します。セットは Dataview からクエリできます。

![スマートフォンで見た Workout Planner: タイマーが動いているガイド付きセッション、+/− ボタンと kg/lb の切り替えがある記録フォーム、トレーニングカレンダー付きのダッシュボードの概要](assets/hero.png)

## 機能

- 前回のセットを初期値にしてレップ数と重量を記録。+/− ボタンと、ワンタップで選べる最近のエクササイズ付き
- 各セットを kg または lb で記録。目の前のプレートの表示どおりに入力できます
- プロトコルでセットに印を付けられます: ドロップセット、マイオレップ、レストポーズ、スーパーセット、21s、または独自のもの
- セットの表は日ごとにまとめられ、日ごとの合計が表示されます。ワンタップで編集できます
- 重量、ボリューム、レップ数、時間、距離、ペース、心拍数のグラフ。進歩しているかどうかを明確に示すトレンド付き
- 週ごとの連続記録（週間目標付き）、トレーニングカレンダー、自己ベスト、総ボリューム、最近のワークアウト、プロトコルの統計を表示するダッシュボード
- 前面と背面の筋肉ヒートマップ。ボリューム、セット数、レップ数で表示
- 休憩タイマー（カウントダウン、インターバル、ストップウォッチ）。プリセット付きで、セットを記録するとリスタートし、iOS と Android でビープ音が鳴ります
- ワークアウトのノートに沿って、エクササイズを 1 つずつ案内するガイド付きセッション
- 計画したワークアウトにかかる時間の見積もり
- 筋力、自重、時間、距離、有酸素運動のエクササイズ、または独自のフィールド
- すべてのセットを 1 つのシンプルな CSV ファイルに保存。Dataview と Templater から読み取れます
- スマートフォン向けの設計: 横スクロールなし、ボタンは常に手の届く場所に
- 24 言語に対応

## はじめに

プラグインを初めてインストールすると、サンプルのノートが追加されます（サンプルのエクササイズ、6 週間分の記録がある 2 つのワークアウト、ダッシュボード、機能紹介）。プラグインはそれらを参照し、**開始** ガイドを開きます。ガイドには機能ごとに短いページがあり、試せる例が含まれています。設定を開く必要はありません。自分のデータを設定する前に、まずは自由に触ってみてください。

### ガイド付きツアー

ツアーは「ガイド付きツアー」というノートを開きます。このノートには、表、グラフ、ダッシュボード、タイマーがあり、それぞれを順番に指し示します。ツアーは 9 つの短いステップで構成されています。

1. **+** ボタンで最初のセットを記録します。保存するとこのステップは完了です。
2. 各行のボタンで、セットを編集または削除します。
3. グラフで進捗を確認します。
4. ダッシュボードで合計とトレンドを確認します。
5. 筋肉ヒートマップで、鍛えた部位を確認します。
6. 休憩タイマーを開始します。開始を押すとこのステップは完了です。
7. リボンのダンベルアイコンを見つけます。どのノートからでも記録フォームを開けます。スマートフォンではコマンドパレットを使ってください。
8. コマンドパレットから任意の **ワークアウトを挿入** コマンドを実行します。実行するとこのステップは完了です。
9. 完了です。

移動するには **戻る** と **次** を使い、終了するには **スキップ** を使います。ツアーが指している部分が表示範囲外にある場合は、**ここを表示** を押すとそこまでスクロールします。`Esc` をいつでも押すとツアーを終了できます。ノートを閉じたり別のファイルに切り替えたりした場合もツアーは終了します。記録が失われることはありません。セットはログに残ります。

サンプルデータを使用している場合、ツアーはそのデータで実行されます。それ以外の場合は、自分の記録を使うため、グラフとダッシュボードはほぼ空の状態から始まります。ノートは一度だけ作成され、サンプルの近くか、保管庫の一番上に置かれます。既存のノートが上書きされることはなく、編集や削除もできます。「Guided tour」という名前のノートがすでにあり、それがツアーのものでない場合は、代わりに「Guided tour 1」（または次の空き番号）を使います。

ツアーをもう一度行いたいですか？ **設定 → Workout Planner → 開始** で **ツアーを開始する** を選ぶか、コマンドパレットから **ツアーを開始** を実行してください。

サンプルやガイドをもう一度使いたいですか？ **設定 → Workout Planner → 開始** で **例を作成** または **はじめにガイドを開く** を選ぶか、コマンドパレット（`Ctrl/Cmd + P`）から **サンプルのメモを作成** または **はじめにガイドを開く** を実行してください。サンプルを作成しても何も上書きされません。もう一度実行すると、不足しているサンプルファイルだけが追加されます。変更したファイルはそのまま残ります。サンプルがまだない場合、ガイドからサンプルを作成するかどうか尋ねられます。空の表、グラフ、ダッシュボードには **サンプルデータで探す** のリンクも表示されます。すでにワークアウトの記録がある場合、サンプルは専用の記録ファイルを持ち、あなたの記録はそのまま残ります。

任意のノート（例: `Push Day`）に表を追加するには、次のようにします。

````markdown
```workout-log
exercise: Bench Press
```
````

表の下の **+** をタップし、レップ数と重量を入力して保存します。表は自動的に更新されます。ブロックを手で書く必要もありません。**ワークアウトグラフ / 表 / タイマー / ダッシュボード / 所要時間を挿入** コマンドを実行すると、フォームが開き、ブロックを挿入してくれます。

## セットを記録する

**+** ボタン（表の下にあります。エクササイズは自動で入力されます）、リボンのダンベルアイコン、または **ワークアウト記録を作成** コマンドで記録フォームを開きます。フォームは前回のセットから始まるので、ほとんどの場合は **+/−** を一度タップして保存するだけです。休憩が終わる前に完了できます。

フォームには、そのエクササイズに合ったフィールドが表示されます。スクワットならレップ数と重量、プランクなら秒数、ランなら距離と時間です（[エクササイズの種類](#エクササイズの種類)を参照）。各セットには、メモとプロトコルを付けることもでき、プロトコルは表にバッジとして表示されます。

重量フィールドには kg/lb の切り替えがあるので、設定が kg でも 225 lb で記録できます。表ではそのセットが「225 lb」と表示されます。グラフ、統計、ボリュームは、すべてのセットを設定の単位に換算します。

ノートからセットを記録すると、そのノートの名前がセットの **ワークアウト** として保存されます。そのため、`workout: Push Day` を指定した表やグラフから後で見つけられます。

## テーブル

`workout-log` ブロックには、エクササイズまたはワークアウトのセットが新しい順に表示されます。同じ日のセットは、その日の合計を示す行の下にまとめられ、各行には編集ボタンがあります。セットを削除するには編集フォームを使います。スマートフォンでは、各セットがコンパクトな行になり、横スクロールは不要です。

<img src="assets/tables.png" width="720" alt="スマートフォンで見た workout-log の表。セットは時間付きの日ごとにまとめられ、ドロップセットのバッジがあり、+ ボタンで開く記録フォームも表示">

```workout-log
exercise: Bench Press
dateRange: 14
targetWeight: 100
targetReps: 8
```

`targetWeight` と `targetReps` を指定すると、表の上に漸進性過負荷の目標が表示されます。

## グラフとトレンド

`workout-chart` ブロックは、1 つの指標の時間経過を描きます。重量、ボリューム、レップ数、推定 1RM、時間、距離、ペース、心拍数に対応しています。グラフのヘッダーには、トレンドが **増加**、**安定**、**減少** のいずれかで表示されます。**安定** とは、期間全体でトレンドラインの動きが平均の 5% 未満であることを意味します。そのため、緩やかでも着実な伸びは「増加」として扱われます。ペースは低いほど良く、線が下がるとそれは改善を示します。スマートフォンでは、グラフは同じ値の表に置き換わります。

`type: e1rm` を指定すると、1 日あたりの最大推定 1RM（Epley 式: `重量 × (1 + レップ数 / 30)`）が表示されます。対象になるのは、重量が正の値で、レップ数が 1 から 12 の整数のセットだけです。ウォームアップセットとドロップセットは除外されます。対象のセットがない日は省略されます。推定値は kg/lb の設定に従います。既定の筋力グラフは引き続きボリュームです。

```workout-chart
exercise: Bench Press
type: e1rm
dateRange: 180
```

API では、`getExerciseStats` に `estimatedOneRepMax` が追加されます。これは設定の重量単位での最良の推定値で、対象のセットがない場合は `null` になります。既存の PR フィールドと CSV の列は変わりません。

![デスクトップで見たベンチプレスの推定 1RM グラフ（増加のトレンドライン付き）と、スマートフォンで見た同じ値の表](assets/charts.png)

```workout-chart
exercise: Squat
type: volume
dateRange: 90
showTrendLine: true
```

## ダッシュボードと筋肉ヒートマップ

`workout-dashboard` ブロックは、総ワークアウト数、週ごとの連続記録、総ボリューム、自己ベストの 4 つの数字から始まります。その下には、週・月・年のクイック統計、ボリュームの推移、最近のワークアウト、プロトコルの統計、計画と実際のワークアウト時間、トレーニングカレンダーが表示されます。トレーニングカレンダーには 1 年分のトレーニング日がボリュームに応じて色付けされ、現在と最長の連続記録も示されます。1 週間に週間目標（設定 → 週間目標、既定では 1）の日数分トレーニングすると、その週が連続記録に加算されます。スマートフォンでは、クイックアクションが先頭に表示され、概要は 2 × 2 のグリッドになります。

<img src="assets/dashboard.png" width="720" alt="スマートフォンで見たダッシュボード: 概要、今週の目標を達成したトレーニングカレンダー、最近のワークアウト、クイック統計">

```workout-dashboard
title: Last three months
dateRange: 90
widgets: [summary, heatMap, volume, recentWorkouts]
```

YAML を書かずにウィジェットとその順番を選ぶには、**ワークアウトダッシュボードを挿入** コマンドを使うか、挿入したダッシュボードの右上にある ⋮ メニューを開いて **ダッシュボードを編集** を選んでください。

その設定ウィンドウで **レイアウト** を **グリッド** にすると、各ウィジェットを自分で配置できます。インベントリの品物のように、ドラッグして移動し、角をドラッグして幅と高さを変え、グリッドの下にドロップすると外せます。キーボードでも操作できます。矢印キーで移動し、Shift と矢印キーでサイズを変え、Delete で外します。グリッドの列数は、ノートの幅に収まる数になります。幅の狭いペインでは、ウィジェットは読み順に並べ直され、スマートフォンでは縦に積み重なります。レイアウトは保存されます。ノートが 1 列にしか収まらない場合（スマートフォンなど）、編集ウィンドウは、保存されている列数を初期値にして、列数を尋ねます。ブロックにはウィジェットごとに 1 行ずつ（列、行、幅、高さ）が保持されます。

```workout-dashboard
layout: grid
columns: 3
grid.summary: 1 1 3 1
grid.heatMap: 1 2 2 2
grid.recentWorkouts: 3 2 1 1
```

筋肉ヒートマップは、直近の 1 週間、1 か月、1 年に鍛えた筋肉を、前面と背面で示します。表示は **ボリューム**、**セット**、**レップ数** から選べます。3 週間脚を鍛えていないといったことに、いちばん早く気づける場所です。その下には、短いトレーニング分析が表示され、前側の筋肉が後側よりもはるかに多く使われているといった偏りを警告します。これは[エクササイズページ](#エクササイズの種類)の筋肉タグを読み取ります。自重や時間を計るエクササイズには重量がないため、**セット** と **レップ数** の表示でだけ色が付きます。

<details>
<summary>筋肉タグ</summary>

タグはリスト、1 語（`tags: chest`）、またはカンマ区切りの 1 行（`tags: chest, triceps`）で指定できます。

大分類: `chest`、`back`、`shoulders`、`biceps`、`triceps`、`forearms`、`traps`、`quads`、`hamstrings`、`glutes`、`calves`、`abs`、`core`

個別の筋肉には、体の中の専用の部位があり、それぞれが大分類に含まれます。大分類のタグは部位全体に広がります。`chest` は胸の 3 つの部位すべてを少しずつ光らせ、`upper_chest` は上部だけを完全に光らせます。

| 大分類      | 個別の筋肉                                  |
| ----------- | ------------------------------------------- |
| `chest`     | `upper_chest`、`mid_chest`、`lower_chest`   |
| `shoulders` | `front_delts`、`side_delts`、`rear_delts`   |
| `back`      | `lats`、`rhomboids`、`lower_back`（または `ql`） |
| `core`      | `obliques`、`serratus`                      |

`petto`（胸）や `schiena`（背中）のように、自分の言語のタグも使えます。プラグインは `muscle-tags.csv`（ログの隣にあります）を使って、それらを上記の大分類に対応付けます。**筋肉タグを管理**（追加、名前変更、検索、重複の確認）から編集するか、直接編集してください。

```csv
tag,muscleGroup,language
petto,chest,it
dorsali,lats,it
```

すでに大分類の名前になっているタグ（`upper_chest`、`Upper chest`、`upper-chest`）は、`muscle-tags.csv` に記載されていなくても常に使えます。

</details>

## タイマー

`workout-timer` ブロックは、カウントダウン、インターバル、ストップウォッチのタイマーです。よく使う休憩時間はプリセットとして保存できます。タイマーをエクササイズまたはワークアウトに紐付けると、セットを記録するたびにリスタートするので、セットの間に操作する必要はありません。`autoStart: true` を指定すると、ノートを開いた時点で開始します。

<img src="assets/timers.png" width="320" alt="スマートフォンで見た 2 つのタイマー: 休憩中のインターバルタイマーと、2 ラウンド目の作業中の Tabata プリセット">

タイマーは iOS と Android でもビープ音を鳴らします。スマートフォンでは、ページをタップした後でないと音が出ません。そのため、`autoStart` で開始したタイマーは、**開始** を一度タップするまで無音のままです。

**設定 → Workout Planner → タイマーのデバイス通知** で、**タイマーの動作中は画面をオンのままにする** は既定でオンです。フォアグラウンドでタイマーが 1 つ以上動いている間、デバイスが対応していれば画面の点灯を維持するように要求します。**タイマーが終了したときに振動する** は既定でオフです。オンにすると、音とは関係なく、ゼロになったときに短く振動します。対応する Android などのデバイスで使えます。iOS では既存の音の通知をそのまま使い、Web の振動は利用できません。これらの機能はブラウザの API をベストエフォートで使っており、実機の Android/iOS では、まだ検証していません。バックグラウンドのアラームにはなりません。`id` を持つタイマーは、ノートを切り替えても動き続けます。画面の点灯を解除するには、一時停止するか、終了させてください。

```workout-timer
type: countdown
duration: 90
exercise: Bench Press
```

インターバルタイマーは、作業と休憩を交互に行えます。表示には **作業** または **休憩** が出て、各フェーズはそれぞれ独自の音で始まります。各ラウンドは作業とそれに続く休憩で構成され、最後のラウンドも含まれます。そのため、次の Tabata は 4 分 00 秒かかります。

```workout-timer
type: interval
work: 20
rest: 10
rounds: 8
```

`preset: Tabata`（作業 20 秒、休憩 10 秒、8 ラウンド）と `preset: EMOM`（1 分ごとに 1 ラウンド、10 分間）は組み込み済みです。同じ名前で保存したプリセットは、これらを置き換えます。

<details>
<summary>すべてのパラメータ</summary>

| パラメータ            | 既定値      | 役割                                                                  |
| --------------------- | ----------- | --------------------------------------------------------------------- |
| `type`                | `countdown` | `countdown`、`interval`、`stopwatch` のいずれか                       |
| `duration`            | `30`        | 秒数（カウントダウン。インターバルでは各ラウンドの作業時間）          |
| `work`                | —           | インターバル: 各ラウンドの作業秒数（`duration` の代わり）             |
| `rest`                | `0`         | インターバル: 各ラウンドの作業の後の休憩秒数                          |
| `rounds`              | `1`         | ラウンド数（インターバル）                                            |
| `sound`               | `true`      | 時間になったらビープ音を鳴らす                                        |
| `autoStart`           | `false`     | ノートを開いた時点で開始                                              |
| `showControls`        | `true`      | 開始、一時停止、リセットを表示                                        |
| `preset`              | —           | プリセットから開始（保存済み、`Tabata`、`EMOM`）。指定したパラメータが優先されます |
| `exercise`、`workout` | —           | このエクササイズまたはワークアウトのセットを記録したときにタイマーをリスタート |
| `superset`            | `false`     | キャンバスへの書き出しのみ: このエクササイズと次のエクササイズをスーパーセットとして描画 |

</details>

## ガイド付きセッション

ワークアウトのノートの先頭にある `workout-session` ブロック（コマンド **ガイド付きセッションを挿入**）は、エクササイズを 1 つずつ案内します。今どのセットか、目標、前回の結果、**セットを記録** ボタン、そしてセットを記録すると始まる休憩タイマーが表示されます。

![スマートフォンで見たガイド付きセッション: 前回の結果とともに 4 セット中の 1 セット目、セットを記録で開いた記録フォーム、タイマーが動いている 4 セット中の 2 セット目](assets/session.png)

````markdown
```workout-session
```

## Squat

```workout-log
exercise: Squat
sets: 4
targetReps: 8
targetWeight: 100
```

```workout-timer
preset: rest
```
````

プランはノート自体です。`exercise` を持つ `workout-log` ブロックごとに 1 つのステップになり、出現順に並びます。各ステップには `sets`、`targetReps`、`targetWeight` があります。休憩は、同じ `##` セクションにある `workout-timer` から取得されます（ない場合は既定のプリセット）。セッションは、このワークアウトで今日記録したセットを数えるため、ノートを開き直しても、続きから再開できます。`sets` のないエクササイズは、後のエクササイズのセットを記録するまで現在のステップのままです。**前へ** と **次へ** で自由に移動できます。

## ワークアウトの所要時間

`workout-duration` ブロックは、ワークアウトのノートにかかる時間を見積もります。タイマーによる休憩時間と、各セットにかかる時間を合計し、前回の実際のセッション時間と並べて表示します。

<img src="assets/duration.png" width="420" alt="休憩時間、セット時間、前回のセッションを表示した所要時間の見積もりカード">

```workout-duration
workout: Workouts/Push Day.md
```

`workout` には、保管庫内のパス、このノートからの相対パス、またはノート名だけを指定できます。省略すると、現在のノートの見積もりになります。レップあたりとセットあたりの秒数は、[設定](#設定)から指定します。

## エクササイズの種類

エクササイズページは、エクササイズフォルダーにあるノートです。そのフロントマターには、記録フォームに何を入力させるか、そしてどの筋肉を鍛えるかを書きます。**エクササイズページを作成** を使うと、ページを作ってくれます。

```yaml
---
exercise_type: strength
tags:
  - chest
  - triceps
---
```

| `exercise_type`      | 記録フォームで入力する項目                    | 受け付ける別名                                               |
| -------------------- | -------------------------------------------- | ------------------------------------------------------------ |
| `strength`（既定）   | レップ数、重量                               | `bodyweight`、`weights`                                      |
| `timed`              | 時間                                         | `duration`、`time`、`timer`、`interval`、`hold`、`isometric` |
| `distance`           | 距離、時間（任意）                           | `running`、`run`                                             |
| `cardio`             | 時間、距離、心拍数（任意）                   | —                                                            |
| `custom`             | `parameters` に列挙したフィールドのみ        | —                                                            |

ヨガも同じように扱えます。各ポーズは `timed` のエクササイズなので、フォームではキープした時間だけを尋ねます。サンプルのノートには、ガイド付きセッションを使った朝のヨガの流れも含まれています。

![スマートフォンで見たヨガの流れ: ダウンドッグのガイド付きセッション、キープ時間だけを尋ねる記録フォーム、キープの表と 1 日の合計](assets/yoga.png)

`type:` は `exercise_type:` と同じように機能します。`parameters` の下に独自のフィールドを追加できます。例えば縄跳びのラウンド数などです。

```yaml
---
exercise_type: timed
parameters:
  - key: rounds
    label: Rounds
    type: number
    required: false
---
```

記録した後にエクササイズの種類を変えた場合は、**エクササイズを変換** で既存のセットを移動し、古いどのフィールドを新しいどのフィールドに入れるかを選べます。

## あなたのデータ

すべてのセットは `workout_logs.csv` の 1 行です。スプレッドシートで開いたり、バックアップしたり、他のファイルと同じように同期したりできます。

```csv
date,exercise,reps,weight,volume,origine,workout,timestamp,notes,protocol
2025-01-17T10:30:00.000Z,Bench Press,8,100,800,[[Push Day]],Push Day,1737138600000,,standard
```

<details>
<summary>列と手動での編集</summary>

| 列                         | 意味                                      |
| -------------------------- | ----------------------------------------- |
| `date`                     | セットを記録した日時（ISO 8601）          |
| `exercise`、`workout`      | エクササイズ名とワークアウト名            |
| `reps`、`weight`、`volume` | ボリュームはレップ数 × 重量               |
| `origine`                  | そのセットを記録したノートへのリンク      |
| `timestamp`                | その行の一意の ID（ミリ秒）               |
| `notes`、`protocol`        | 自由記述のメモとトレーニング技法          |

独自のフィールドを持つエクササイズの種類（`duration`、`distance`、`heartRate`、または `parameters` で定義したもの）は、末尾に列を追加します。最後の列 `weightUnit` は `kg` または `lb` です。その行の `weight` と `volume` の単位を示します。空の場合は、設定の単位になります。

ファイルを手で編集する場合は、ヘッダー行を残し、カンマ、引用符、改行を含む値は二重引用符で囲んでください。`=`、`+`、`-`、`@` で始まるメモは、スプレッドシートで数式として扱われないように、先頭に `'` を付けて保存されます。プラグインは、その `'` を表示しないように隠します。

</details>

すべてのデータは保管庫の中に残ります。プラグインがクリップボードに書き込むのは、コピーのバッジ（ダッシュボードの筋肉タグ）をクリックしたときだけです。クリップボードを読み取ることはありません。

### DataviewとTemplater

プラグインは読み込まれると `WorkoutPlannerAPI`（`window.WorkoutPlannerAPI` としても利用可能）を公開します。

```dataviewjs
const s = await WorkoutPlannerAPI.getExerciseStats("Bench Press");
dv.paragraph(`Best: ${s.prWeight} × ${s.prReps} on ${s.prDate}`);
```

<details>
<summary>API リファレンスと追加の例</summary>

| メソッド                     | 戻り値                                                                                                                                                                                                                                               |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getWorkoutLogs(filter?)`    | セットの配列。各セットは `date`、`exercise`、`reps`、`weight`、`volume`、`workout`、`notes`、`timestamp`、`protocol` を持ちます。`weight` と `volume` は設定の単位で、`enteredWeight` と `enteredUnit` は記録したときの値です                                    |
| `getExerciseStats(exercise)` | `estimatedOneRepMax`、`totalVolume`、`maxWeight`、`prWeight`、`prReps`、`prDate`、`totalSets`、`averageWeight`、`averageReps`、`lastWorkoutDate`、`trend`                                                                                             |
| `getExercises(filter?)`      | 並べ替えられたエクササイズ名。エクササイズページのファイル名（サブフォルダーを含む）、またはエクササイズページがない場合は記録内の名前です。`{ tag: "chest" }` を指定すると、そのタグを持つページのエクササイズだけに絞り込みます。エクササイズページがなければ空になります。 |

`getWorkoutLogs` は、`exercise`（部分一致、大文字小文字を区別しない）、`workout`、`dateRange: { start, end }`、`protocol`、`exactMatch` を受け付けます。

Dataview で直近のスクワットを表示する例:

```dataviewjs
const logs = await WorkoutPlannerAPI.getWorkoutLogs({
  exercise: "Squat",
  dateRange: { start: moment().subtract(30, "days").format("YYYY-MM-DD") },
});
dv.table(
  ["Date", "Reps", "Weight"],
  logs.map((l) => [l.date.slice(0, 10), l.reps, l.weight]),
);
```

[Templater](https://github.com/SilentVoid13/Templater) のテンプレートで、最新の数値からノートを始める例:

```markdown
## Squat

<%\*
const s = await WorkoutPlannerAPI.getExerciseStats("Squat");
tR += s.totalSets
? `Best ${s.prWeight} × ${s.prReps} (${s.prDate}), last session ${s.lastWorkoutDate}`
: "No squats logged yet";
%>
```

</details>

## 設定

CSV とエクササイズのフォルダー、既定の重量単位、**+/−** ボタンの重量の刻み幅、タイマーのプリセット、独自のプロトコル（名前、短いラベル、色）、そして時間の見積もりに使う 1 レップと 1 セットあたりの秒数を設定します。**詳細設定** の **すべて実行** を使うと、アップグレード後のメンテナンス作業をすべて実行できます。

重量単位を変更しても、古いセットのラベルは変わりません。各セットは、記録されたときの単位を保持します。

## トラブルシューティング

- **`workout-block`（Workout Block）との競合。** 両方のプラグインが `workout-log` のコードブロックを登録し、既定の記録ファイル名として `workout_logs.csv` を使います。どちらか一方のプラグインを無効にしてから、もう一方を使ってください。

- **表またはグラフが空になる。** エクササイズ名と `dateRange` を確認してください（グラフの既定は直近 30 日です）。`exactMatch: true` を指定している場合は、名前が完全に一致している必要があります。
- **ヒートマップにエクササイズが表示されない。** そのエクササイズページに筋肉の `tags` が必要で、エクササイズフォルダーにある必要があります。自重や時間を計るエクササイズは、**セット** または **レップ数** の表示でだけ表示されます。
- **プランクで記録フォームがレップ数と重量を尋ねる。** エクササイズページで `exercise_type: timed` を設定してください。
- **スマートフォンでタイマーが鳴らない。** **開始** を一度タップしてください。スマートフォンは、ページに触れるまで音を止めています。

## インストール

### コミュニティプラグインから

1. **設定 → コミュニティプラグイン** を開きます
2. **Workout Planner** を検索します
3. **インストール**、続けて **有効化** を選びます

### 手動

1. [最新のリリース](https://github.com/SpatariuRares/obsidian-workout-plugin/releases/latest)から `main.js`、`manifest.json`、`styles.css` をダウンロードします
2. フォルダー `your-vault/.obsidian/plugins/workout-planner/` を作成します
3. ダウンロードしたファイルをそのフォルダーにコピーします
4. **設定 → コミュニティプラグイン** でプラグインを有効にします
